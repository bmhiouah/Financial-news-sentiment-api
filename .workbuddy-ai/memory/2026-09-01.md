# 2026-09-01

## Analyse tab: single-equity + Simple vs Benchmark strategy comparison

Added a strategy comparison to the Analyse tab of the FastAPI app.

**New backend files**
- `src/financial_sentiment/strategy/metrics.py` — pure-python metrics from a daily
  equity curve: `total_return`, `cagr` (365.25 calendar days), `max_drawdown`
  (negative), `sharpe_ratio` (sqrt(252), rf=0). Exposes `METRIC_KEYS` /
  `METRIC_LABELS` so the UI row order comes from one place.
- `src/financial_sentiment/strategy/comparison.py` — `StrategyComparator`.
  Loads the price/sentiment DataFrame **once** and passes it to both backtests
  (`Backtester.run(equity, df=df)`), guaranteeing identical data/window.

**Changed**
- `strategy/strategy.py` — new `BuyAndHoldStrategy` (one long on the first tick).
  Benchmark `Portfolio` uses `trade_size = initial_capital` and
  `stop_loss=-inf / stop_win=inf`, `Backtester(min_signals=1)`.
- `strategy/backtester.py` — `run()`, `count_signals()`, `validate()` now accept an
  optional pre-loaded `df` (backward compatible).
- `api/schemas.py` + `api/routes/backtest.py` — new `POST /backtest/compare`.
- `api/static/analysis.html` / `.js` / `style.css` — equity slicer switched from
  checkboxes to radios (single equity); new "Simple vs Benchmark Strategy" card
  with an HTML heatmap (4 metrics x 2 strategies, winner highlighted + ★) and a
  Plotly equity-curve chart. "Run Backtest" now renamed "Run Backtest & Compare"
  and chains `/backtest/compare`.
- `README.md` — documented the endpoint + comparison section.

**Decisions**
- Benchmark = Buy & Hold (100% invested day 1) — trivially free of look-ahead and
  the standard reference for "does the sentiment strategy beat just owning it".
- The 4 metrics: Total Return, CAGR, Max Drawdown, Sharpe. All are
  "higher is better" as stored (MDD is negative), so the heatmap winner is just
  `max()` per row.
- Heatmap is an HTML/CSS table (not Plotly) — raw values are not comparable across
  rows, so colour encodes only within-row ranking, and the real value is printed.
- CAGR/Sharpe are annualised; a warning banner shows when the window < 120
  trading days (current data is only ~2 months).

## SQLite → PostgreSQL migration (FINAL, completed this session)

Storage moved from `data/news.db` (sqlite3) to PostgreSQL. The prior summary
described this as done but the CODE was never actually written to disk — only
`.env` + `pgdata` survived. Re-did the real work.

**Code changes**
- `src/financial_sentiment/config.py` — `load_project_env()` now called at import;
  new `database_url` setting (reads `DATABASE_URL`, default
  `postgresql:///financial_sentiment`); `DATABASE_URL` module constant.
- `src/financial_sentiment/repository.py` — full rewrite to psycopg 3.x.
  Placeholders `%s`; `INSERT ... ON CONFLICT (cols) DO NOTHING` instead of
  `INSERT OR IGNORE`; `GENERATED ALWAYS AS IDENTITY` keys; `_conn` is a
  `@contextmanager`. All method signatures preserved (app untouched).
- `src/financial_sentiment/api/main.py` — lifespan calls `Repository().init()`.
- `scripts/pg_server.py` (new) — `pgserver` bundled PG: start/stop/status/uri/psql.
  `cleanup_mode=None` so the server survives across tool calls; data dir
  `~/.financial_sentiment/pgdata` (space-free path).
- `scripts/migrate_sqlite_to_postgres.py` (new) — idempotent copy from
  `data/news.db` (ON CONFLICT DO NOTHING). `--dry-run` supported.
- `scripts/backfill_returns.py` — `?` placeholders → `%s`.
- `scripts/run_api.py` — `_check_database()` fails fast if PG unreachable.
- `requirements.txt` + `pyproject.toml` — `psycopg[binary]` added.
